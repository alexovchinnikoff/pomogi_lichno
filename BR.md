# 🐛 Анализ ключевых баг-репортов (API проекта «Помоги лично»)

Этот документ содержит детальный разбор наиболее показательных дефектов, выявленных в ходе тестирования API. Эти кейсы демонстрируют работу с «серыми зонами», противоречиями в требованиях и проблемами интеграции.

## 1. Кейс: Противоречие в логике обработки ошибок (Блок `/share/`)
**ID бага:** BR_APIdoc_shr_1
**Приоритет:** Высокий
**Эндпоинт:** `PATCH /share/`
**Метод:** PATCH

### Суть проблемы
В требованиях (ТЗ) и документации Swagger были указаны **взаимоисключающие** ожидаемые результаты для сценария передачи некорректного значения параметра `icon`:
*   Вариант А: `400 Bad Request` (ошибка валидации).
*   Вариант Б: `404 Not Found` (объект не найден).

### Фактическое поведение системы
При воспроизведении сценария с некорректным значением (`"icon": "error"`) сервер стабильно возвращал код **400 Bad Request** с детализацией ошибки:
```json
{
  "error": "Валидация завершилась с ошибкой",
  "details": {
    "icon": ["Выбрана неправильная иконка."]
  }
}
